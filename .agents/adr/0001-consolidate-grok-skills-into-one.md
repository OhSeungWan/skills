# grok-code·grok-spec·grok-quiz 세 스킬을 분기 3개짜리 단일 grok 스킬로 통합한다

원 레포(ai-handoff)의 ADR-0001은 "스킬들이 독립 설치되므로, 끊어질 수 있는 크로스 참조보다
관리 가능한 드리프트가 낫다"는 근거로 참조 파일을 스킬마다 복제했다. 이 플러그인 전환이 그
전제를 무너뜨렸다: 플러그인은 세 스킬을 항상 한 몸으로 배포하므로 참조가 끊길 위험이 애초에
없고, 남는 것은 드리프트 비용뿐이다 — 실제로 `writing-quizzes.md`가 3벌로,
`intuition-first.md`·`notion-assembly.md`가 2벌로 갈라진 것이 관측됐다(md5 대조).

그래서 세 스킬을 파이프라인 하나(대상 해석 → 맥락 → 멘탈모델+퀴즈 설계 → 조건부 그림 →
Litt 자기점검 → 출력 → 보고)에 분기 3개(code/spec/quiz)를 얹은 단일 `grok` 스킬로 합쳤다.
분기 간 다른 것은 입력 타입·고유 섹션·출력 채널·게이트 강도뿐이며, 분기 전용 규칙은
`literate-code.md`(code)·`surfacing-decisions.md`(spec)로 격리해 분기 혼선을 막는다.

이 결정은 원 레포의 ADR-0001과 ADR-0002(grok-quiz standalone, 통합은 후속 결정으로 유보)를
대체한다.

## Considered Options

- **(i) 세 스킬 유지 + shared/ 디렉터리 + sync 스크립트** — 기각: 동일 복사본 문제만 풀고
  도메인 변형 3벌(quiz 방법론 등)의 드리프트는 남는다. sync 기계장치도 추가된다.
- **(ii) 세 스킬 유지 + 변형은 의도된 분화로 방치** — 기각: 유지보수 주체가 1인인데 사본
  추적이 이미 실패한 것이 관측됐다.
- **(iii) 단일 스킬 + 분기 (채택)** — 변형이 분기 레퍼런스로 승격되어 중복이 정의상 소멸.
  sync 장치 불필요. 비용: 분기 규칙이 섞일 리스크(전용 레퍼런스 격리로 방어), 호출이
  `/grok-code` 대신 `/grok <대상>`(1단계 자동 판별 + 명시 오버라이드).

## Consequences

Litt 규칙·퀴즈 방법론·자기완결 검사·Notion 조립이 각 1벌이 된다. 분기 추가(예: PR 리뷰용)는
분기 표 한 줄 + 전용 레퍼런스 한 파일로 가능하다. 반대로 스킬을 다시 쪼개 개별 배포하려면
공유 레퍼런스를 도로 복제해야 한다 — 그 시점에 이 ADR의 전제(한 몸 배포)가 다시 평가 대상이
된다.
