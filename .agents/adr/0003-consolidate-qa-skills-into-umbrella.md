# qa 와 design-qa 를 /qa 우산 스킬 하나로 합친다

[#10](https://github.com/OhSeungWan/skills/issues/10)은 design-qa 를 별도 스킬로 결정했다 — "화면 대장이라는 트랙보다 오래 사는 자산과 무거운 setup 이 `qa`를 두 배로 부풀리고, `qa`의 분기 판별(시트 상태 분포 읽기)이 scan 에는 성립하지 않는다"는 근거였다. 이 ADR 은 그 결정을 뒤집는다([#17](https://github.com/OhSeungWan/skills/issues/17) 제약 1).

뒤집는 근거는 QA 루프가 **파이프라인**이 됐다는 것이다: setup(정답지 해석) → scan(기계 발견) → collect(사람 발견) → fix(수정) → 사람 눈 → 오라클 갱신. 스킬 둘로 가르면 값 결정 표와 시트 스키마를 한쪽이 "가리켜서 물려받는" 간접층이 생기고, 루프 전체가 어느 문서에도 그려지지 않으며, 로직/플로우 검사(#22)가 붙을 때 겹치는 표면이 셋이 된다. #10의 두 우려는 다른 수단으로 각각 해소된다 — 비대화는 ADR-0001(grok)이 확립한 **분기 전용 레퍼런스 격리**로(SKILL.md 는 루프 그림·공통 표·분기 표만, 분기 규칙은 `references/` 다섯 파일), 분기 판별 불성립은 **인자 필수**로(무인자는 상태 출력만, 실행 없음).

대상 레포 상태 디렉터리도 `.design-qa/` 에서 `.qa/` 로 개명한다 — 대장·config 는 이제 scan 전용이 아니라 루프 공용 자산이다(오라클 좌표가 이미 거기 산다).

## Considered Options

- **(i) 별도 스킬 유지 + README 에 루프 그림** — 기각: 값 결정·시트 스키마의 포인터 상속이 남고, 그림과 실제 규칙이 다른 파일에 살아 드리프트가 기본값이 된다.
- **(ii) 우산 스킬 + 분기 레퍼런스 (채택)** — 공통이 한 번, 루프가 한 그림, 분기 추가는 레퍼런스 한 장. 비용: `/design-qa` 호출 경로 소멸(주 사용자 1인이라 이행 비용 무시 가능), 레퍼런스 파일이 늘어 처음 읽는 사람의 점프가 한 번 는다.
- **(iii) 전부 SKILL.md 한 파일에 인라인** — 기각: #10이 짚은 비대화가 그대로 실현된다. scan 만 100줄이 넘는다.

## Consequences

- `oracle` 은 우산에 넣지 않는다 — 편집 주체가 층 오너(PM/BE/FE)라 루프 스텝이 아니라 정답지 편집기이고, 수명도 트랙 단위로 다르다. 루프 그림에서 화살표로만 참조한다.
- scan 이 만드는 행의 `비고` 표식은 `자동 생성 (qa scan)` 으로 바뀌되 옛 `자동 생성 (design-qa)` 도 같은 신호로 읽는다 — 구분자는 접두 `자동 생성 (` 이다.
- 분기 추가(플로우 검사, #22)는 분기 표 한 줄 + 레퍼런스 수정으로 가능하다. 반대로 scan 을 다시 독립 배포하려면 공통 표를 도로 복제해야 한다 — 그 시점에 이 ADR 의 전제(한 몸 배포)가 재평가 대상이 된다.
