# 플로우 정답지는 사람 확정 게이트를 거친 단일 출처뿐이다

> Supersedes [ADR-0004](./0004-flow-checks-derive-from-oracle.md) — 원칙과 경계는 계승하고 출처를 일반화한다.

플로우 검사의 기대값 출처를 "오라클 ④ 확정"에서 일반화한다. **레포당 정답지 출처는 하나**이고, 그 출처의 **사람이 확정한 항목만** 검사가 된다 — 출처가 하나여야 실패가 곧 결함이라는 ADR-0004의 논지는 그대로다. 출처는 둘 중 하나다:

- **트랙 레포** — 오라클 ④ 화면 기대의 `확정` 항목. 확정 자리는 노션 DB(층 오너 FE).
- **트랙 없는 레포** — 노션 요구사항 문서(포맷 비통일)에서 추출한 기대 문장. 확정 자리는 레포 정답지 파일 자체.

물화는 공통이다: `.qa/flows/<프로젝트 slug>.yaml` **정답지 파일**이 setup/scan의 유일한 읽기 심이다. 트랙 레포에선 오라클 스냅샷의 착지(파생물 — ADR-0004의 "대장 머리말 `oracle.snapshot`"을 대체한다), 문서 레포에선 정본이다. scan 은 `.qa/flows/*.yaml` 을 병합해 읽고 파일 머리 `retired: true` 는 건너뛴다 — 프로젝트가 수명 경계다(문서 갱신·확정·종결이 같이 움직인다).

파일 규칙:

1. **항목은 문장이다.** 칸은 넷 — `id`(프로젝트 slug 접두사 + 번호) · `문장` · `상태`(`잠정`/`확정`/`폐기`) · `출처`(노션 블록/문서 URL). 원자 검사(expect 원시어)로의 분해는 대장 `flows:` 를 쓰는 단계의 에이전트 몫이고, 화면 오배치·분해 오류는 기존 `confidence` 게이트(setup 검증)가 잡는다. 제품 게이트(사람·문장)와 기술 게이트(confidence·분해)는 직교한다.
2. **확정만 분해한다.** 잠정은 검사하지 않고 미커버로 센다. 요구사항 문서엔 `FE 기본값` 이 없어 ADR-0004 경계 3(잠정은 FE 기본값 검사 후 리포트만)은 문서 파이프에 존재하지 않는다.
3. **재추출은 자동 전이 금지.** 문서가 바뀌어 확정 항목과 어긋나는 추출이 나오면 `stale: <사유>` 표시 + 보고만 하고 전이는 사람 몫이다 — 강등도 제품 판단이다. 신규 후보만 잠정으로 추가한다.
4. **번호 재사용 금지, 폐기는 상태.** 오라클 스킬의 규칙을 파일에 그대로 이식한다.

추출·확정·분해 워크플로는 `/qa flows` 분기가 전담한다(확장 층). 문서 입력은 config `requirements:`(프로젝트 slug → 노션 URL 목록) — 없으면 물어서 기록한다.

ADR-0004의 경계는 출처 불문 유지된다: 읽기 전용 흐름만 검사 · 전제 못 만들면 미커버로 셈 · `confirmed` 검사 실패만 행 · ② 정책 층은 직접 분해하지 않음.

## Considered Options

- **(i) 노션 표 경량 오라클** — 기각: 동료 레포마다 노션 DB 생성은 #32가 제거한 개인 인프라의 재도입이고, SQL 워크스페이스 쿼터 실측 문제도 그대로다.
- **(ii) 대장 직행(추출 결과를 곧장 `flows:` 후보로)** — 기각: 파생물인 대장이 정본을 겸하게 되고, 재추출 diff 기준이 사라진다.
- **(iii) 파일에 원자 단언 직접 저장** — 기각: 사람이 확정하는 대상이 제품 결정이 아니라 검사 구현이 된다 — 게이트 성격이 섞인다.
- **(iv) 프로젝트별 정답지 파일 = 심 (채택)**.

## Consequences

- scan/setup 의 정답지 읽기 경로가 하나로 — 트랙 분기가 코드 경로에서 소멸한다. 코어 문서 개정(#37) 반영 시 이 ADR 기준.
- `/oracle` 스킬은 무변경 — 오라클은 트랙 구현체 명칭으로 유지되고, 신조어는 "정답지 파일" 하나다(CONTEXT.md).
- 확장(/qa flows)의 구현 반영은 사내 공유 맵(#31)의 목적지 밖 — 다음 효력.
