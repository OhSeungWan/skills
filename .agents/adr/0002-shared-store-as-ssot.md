# 커밋되지 않는 개인 문서는 공용 git dir 안 스토어를 정본으로 두고 워크트리에는 심링크만 둔다

워크트리를 여러 개 쓰면 `CONTEXT.md`·`CLAUDE.local.md`·`docs/agents`·`docs/adr` 같은 개인 문서가
워크트리마다 갈라진다. 커밋해서 공유할 수는 없다 — 개인 지침이고, 남의 repo에서는 올릴 자리도
없다. 그래서 실체를 `.git/shared-store/`(공용 git dir 안) 한 곳에 두고 각 워크트리의 경로는
그리로 향하는 심링크로 만든다. 경로는 `git rev-parse --git-common-dir`로 계산하므로 어느
워크트리에서 실행해도 같은 곳을 가리키고, 설정 파일이 따로 필요 없다.

이 결정을 스킬(`shared-store`)로 패키징하면서 스토어 자체를 git repo로 만들었다. 손으로 운용하던
동안 스토어는 버전 관리 밖이었고, 18KB짜리 용어집을 잘못 덮으면 복구 수단이 없었다.

무엇을 링크할지는 스토어 안 `manifest`가 정한다. 스크립트에 경로를 하드코딩했더니 repo 두 곳에서
이미 갈라졌다 — 한쪽은 ADR을 스토어에 두고, 다른 쪽(이 repo)은 ADR을 `.agents/adr/`에 추적하며
ignore 수단도 `info/exclude`가 아니라 커밋된 `.gitignore`였다. 목록이 스토어 안에 있으면 모든
워크트리가 항목 정의까지 공유하고, repo마다 다른 관례를 스킬 수정 없이 담는다.

## Considered Options

- **(i) 개인 문서를 그냥 커밋** — 기각: 팀 repo에 개인 지침을 올릴 수 없고, `CLAUDE.local.md`는
  정의상 로컬 파일이다.
- **(ii) 워크트리마다 사본** — 기각: 갈라짐이 기본값이 된다. 실제로 rentre repo에서 워크트리 5곳 중
  2곳이 갈라지고 같은 ADR이 `0001`과 `0004`로 이중 번호를 얻은 것이 관측됐다.
- **(iii) 중앙 개인 docs repo 하나 + repo별 서브디렉토리** — 기각: repo↔디렉토리 매핑 설정이
  새로 필요하고, 그 매핑이 어긋나는 것이 다음 사고다. git dir 트릭의 값은 설정이 없다는 데 있다.
- **(iv) 공용 git dir 스토어 + 심링크 (채택)** — 설정 없이 경로가 계산되고, repo를 지우면 딸린
  문서도 함께 사라진다. 비용: 심링크는 `git worktree add`로 딸려오지 않으므로 워크트리마다
  링커를 1회 실행해야 하고, 추적 중인 파일이 하나라도 있으면 그 경로 링크가 통째로 skip된다.

## Consequences

skip이 스크립트 출력에만 남아 사실상 조용히 지나가기 때문에, 링커만으로는 부족하고 실측 동작이
따라와야 한다 — `doctor`가 `git worktree list` 전체를 돌며 `tracked`·`diverged`·`missing`·`exposed`를
판정하고, `adopt`이 추적 파일을 스토어로 되돌린다. `adopt`의 `git rm --cached`는 브랜치 단위이므로
다른 워크트리는 그 커밋을 받은 뒤 재링크해야 끝난다.

새 워크트리 자동 복구는 세션 시작 훅이 맡되, 훅은 스킬 파일이 아니라 **스토어에 심긴 링커 사본**
(`<스토어>/link.sh`)을 실행한다. 그래서 `link`가 실행될 때마다 자기 사본을 스토어에 심는다. 훅이
플러그인 캐시 경로를 하드코딩하면 프로파일·버전이 바뀔 때 조용히 깨지고, 이 세팅의 실패는 원래
조용하다는 게 문제이기 때문이다. 대가는 링커가 스토어에 두 벌(스킬 원본·스토어 사본)로 존재하는
것인데, `link`가 매번 `cmp`로 갱신하므로 갈라지지 않는다.

스토어가 부모 repo의 `.git/` 안에 있으므로 부모를 지우면 문서도 사라진다. 유실 대비는 스토어에
private 리모트를 붙이는 것으로 하되, 자동 push는 하지 않는다 — 개인 문서를 조용히 외부로 보내는
일이라 승인이 필요하다.
