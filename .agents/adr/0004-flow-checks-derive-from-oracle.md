# 플로우 검사의 정답지는 오라클 ④ 화면 기대의 확정 항목만이다

> Superseded by [ADR-0005](./0005-flow-answer-key-is-single-human-confirmed-source.md) — 출처를 "사람 확정 게이트를 거친 단일 출처"로 일반화.

`/qa scan` 에 붙을 플로우 검사(조작 → URL·상태 단언, [#22](https://github.com/OhSeungWan/skills/issues/22))의 기대값은 **오라클 ④ 화면 기대 층의 `확정` 항목에서만** 온다. 시안(피그마)이 폴리싱의 정답지이듯 오라클이 로직의 정답지다 — 기대값의 출처가 하나여야 실패가 곧 결함이다.

경계 네 개가 이 결정의 본체다:

1. **읽기 전용 흐름만 검사한다.** 전송·주문·첨부처럼 서버 상태를 바꾸는 조작은 `forbidden` 그대로다 — team 존은 공유 환경이고 실제 주문이 생긴다. 전제 상태(읽기 전용 방·빈 방·만료 임박)를 못 만드는 항목은 검사하지 않고 **미커버로 센다** — 침묵하지 않는다.
2. **`confirmed` 검사 실패만 행이 된다.** 검사 자체가 틀리면 모든 실패가 오탐이므로, setup 검증 한 바퀴에서 통과한 검사만 `confidence: confirmed` 를 얻는다. 검증에서 실패한 검사는 사람이 "검사가 틀림 / 진짜 결함"을 가르고, 진짜면 setup 이 그 자리에서 행을 만든다. `guessed` 검사의 실패는 리포트에만 남는다.
3. **잠정 항목은 `FE 기본값`을 검사하되 리포트만** — 잠정은 바뀌는 값이라 시트에 쌓으면 확정 순간 오탐 이력이 된다.
4. **② 정책 층은 직접 분해하지 않는다.** 정책은 화면에서 직접 안 보이고 ④ 문장이 인용한다. 인용 안 된 정책이 발견되면 그건 ④ 항목 누락이라 오라클 쪽 일이다.

오라클은 **setup 때 1회** 읽어 대장에 굳힌다(대장 머리말 `oracle.snapshot`) — scan 은 오라클을 부르지 않는다. 노션 SQL 은 워크스페이스 공용 쿼터에 걸리는 것이 실측됐고, 매 실행이 정답지 원본을 부르지 않는 것은 scan 이 피그마에 이미 적용한 원칙이다.

## Considered Options

- **(i) 스펙 이슈·티켓 AC 를 정답지로** — 기각: 산문이고 갱신이 안 된다. 오라클이 바로 그 문제를 풀려고 만든 물건이다(항목 단위 상태·오너·출처).
- **(ii) 대장 도달 경로의 회귀만 검사** — 부산물로 켠다(`confirmed` 캡처의 `arrival_text` 실패 = 회귀 신호). 단독으로는 기각 — 대장 썩음과 코드 버그를 구분하지 못하고, 커버 범위가 "이미 걷는 경로"뿐이다.
- **(iii) 에이전트가 기대값을 추론** — 금지. 오라클이 없는 기대는 제품 결정이고, 제품 결정 자동화는 #17 이 스코프 밖으로 못 박았다.
- **(iv) 오라클 ④ 확정 + 위 경계 (채택)**.

## Consequences

- 오라클이 없는 트랙에는 플로우 검사도 없다 — 오라클을 만들지 말지가 트랙 착수 때의 결정이 된다.
- 실패 행은 재현 증거(스텝·기대·실제·실패 시점 스크린샷)를 달고 `성질=로직` · `사람 확인 필요` 로 들어간다. fix 의 정적 추적 원칙은 그대로다 — 재현은 scan 이 이미 했다.
- 머지 뒤 재검 통과는 행 코멘트로만 남긴다. agent 의 `배포 완료` 전이는 승격 스위치 셋째 칸이다 — "관측 가능한 건 agent 가 찍는다"는 원칙과 어긋나는 잠정 상태임을 인정하고, 배포 SHA 관측 배관이 붙으면 재평가한다.
