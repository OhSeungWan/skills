# oracle

채팅:견적 1:n 1차의 QA 정답지를 항목 단위로 고친다. **오라클이 최상위 정본이다** — 시안·티켓 AC·BE ADR 은 출처일 뿐이고, 오라클을 고치지 않은 결정은 유효하지 않다.

## 좌표 (하드코딩 — 탐색하지 말 것)

- 정본 Doc: https://app.notion.com/p/3bc48a0332088166a83ac3d8c41ed5cb (`RPB-10015`)
- 항목 DB data source: `collection://7e5f0426-7fb6-4b42-909e-24785c6d9c23` — title 키는 **`항목 ID`**
- 스키마 8칸: `항목 ID` · `층`(①용어 ②정책 ③계약값 ④화면) · `문장` · `상태`(`잠정`/`확정`/`폐기`) · `오너` · `출처` · `FE 기본값` · `미확정 시 막히는 것`

## 토큰 규칙

**행 단위로만 읽고 쓴다.** `항목 ID`·`상태`·`오너`로 조건 조회(SQL)하고, 정본 Doc 전체나 DB 전체를 fetch 하지 않는다. 층 구분·ID 체계·화면 13종 번호가 궁금할 때만 정본 Doc 을 연다.

## 동작 3가지

1. **갱신** — 결정이 바뀌면 해당 행의 `문장`·`출처`를 고친다. `출처`는 필수(GitHub 이슈 · ADR · 피그마 node-id · PD/BE 발화 링크) — 출처 없는 갱신은 하지 않는다.
2. **확정/반려** — `잠정 → 확정`으로 바꿀 수 있는 건 **그 층의 오너뿐**이다(①② PM · ③ BE · ④ FE). 오너가 아니면 의견을 `출처`에 링크로 남기고 상태는 두라. 확정 시 `미확정 시 막히는 것`은 비운다.
3. **신규/폐기** — 새 항목은 그 접두사의 최대 번호 + 1. **번호 재사용 금지** — 폐기는 행 삭제가 아니라 `상태 = 폐기`. `잠정`으로 만들면 `FE 기본값`과 `미확정 시 막히는 것`을 반드시 채운다.

## 갱신 트리거 — 셋 중 하나가 나면 오라클을 먼저 고치고 넘어간다

1. **결정 티켓 종결** — 결정이 닫히면 해당 항목 갱신.
2. **티켓 PR 머지** — 구현이 오라클과 다르게 착지했으면 둘 중 하나가 틀린 것. 판정해서 고친다.
3. **QA "버그 아님" 판정** — 구현이 맞고 오라클이 틀린 경우. 오라클을 고쳐야 판정이 유효해진다.

## 노션 도구가 없을 때 (폴백)

노션 MCP 가 이 세션에 없으면 쓰기를 시도하지 말고, **변경안 표**(항목 ID · 바꿀 칸 · 이전 → 이후 · 출처)를 출력해 사람이 노션에서 직접 반영하게 한다.

## 하지 않는 것

- QA 케이스 시트 작성 — 시트는 오라클의 파생물이고 별도 스킬(/qa)의 일이다.
- BE 계약 원문 복제 — ADR·태스크가 정본. ③층엔 화면 판정이 분기하는 값만 담고 나머지는 링크한다.
- 통짜 승인 — 확정은 항목 단위다. 부분 확정이 정상 상태다.
