# qa

트랙 하나의 QA 루프 전체를 노션 **QA 시트** 한 장 위에서 분기 4개로 돈다. 기계가 먼저 채우고(scan), 사람이 쌓고(collect), agent가 고치고(fix), 사람이 **team 존**에서 눈으로 확인해 닫는다.

```
[스펙 이슈 · 오라클] ──setup──> 화면 대장 ──scan(시안 대조)──> 행: 사람 확인 필요 ─사람 검수─┐
                                                                                          ├─> 시작전 ──fix──> 배치 PR ──> 리뷰 → PR 완료 ──team 존 사람 눈──> 배포 완료
사람 QA 세션의 러프한 보고 ────────collect──────────────────> 행: 시작전 ────────────────┘         └─ "버그 아님" ──> /oracle 갱신
```

| 분기 | 하는 일 | 규칙 |
| --- | --- | --- |
| `setup` | 화면 대장 생성·갱신 — 피그마 짝짓기 · 셀렉터 유도 · 한 바퀴 자동 검증 | [`references/setup.md`](references/setup.md) |
| `scan` | 대장대로 team 존을 찍어 시안과 대조, 새로 발견한 폴리싱 결함만 행 생성 | [`references/scan.md`](references/scan.md) · 판정 문안 [`references/judge.md`](references/judge.md) |
| `collect` | 러프한 보고를 항목 단위로 쪼개 시트에 쌓기 | [`references/collect.md`](references/collect.md) |
| `fix` | `시작전` 항목을 코드에서 원인 짚어 수정, 통합 브랜치로 배치 PR | [`references/fix.md`](references/fix.md) |

scan·setup 규칙의 실측 근거는 [`references/rationale.md`](references/rationale.md) — 규칙을 바꿀 때만 읽는다.

## 상태 머신

```
작성 중 ──사람이 제출──> 시작전 ──집어듦──> 진행 중 ──배치 PR──> 리뷰 ──머지 감지──> PR 완료
                          ^            │                                          │
                          │            └──원인 미특정 · 스펙대로 · 보류──> 사람 확인 필요
                          │                                                       │
                          └──────────────사람이 정보 보강─────────────────────────┘

PR 완료 ──team 존에서 사람 눈──> 배포 완료
```

**agent가 관측할 수 없는 것만 사람이 찍는다** — 다 썼다는 의사(`시작전`)와 눈으로 봤다는 판정(`배포 완료`) 둘뿐이다. 나머지 전이는 전부 관측 가능한 사실이라 agent가 찍는다. 관측으로 알 수 있는 걸 사람에게 시키면 그 칸은 영원히 비어 있다.

**큐 조건은 `시작전` 정확히 하나다.** `작성 중`도, 상태가 빈 행도 집지 않는다 — 사람이 노션에서 타이핑하는 중인 행을 agent가 집어들면 미완성 정보로 엉뚱한 걸 고친다. scan이 만든 행은 `사람 확인 필요`로 들어온다 — 오탐 검수 전에 큐에 못 들어가게 막는 자리다. 사람이 검수해 `시작전`으로 밀면 그때부터 fix의 큐다.

## 값 결정 (모든 분기 공통, 맨 먼저)

| 값 | 결정 방법 |
| --- | --- |
| QA 시트 | 인자로 받은 노션 DB URL이 1순위, 다음이 repo 관례 문서(`CLAUDE.md` · `docs/agents/qa.md` 류), 없으면 트랙명·브랜치명으로 워크스페이스 검색 후 **후보를 제시하고 확인받는다** |
| 시트 부모 페이지 | `collect`가 시트를 새로 만들 때만 필요하다. 위치는 추론하지 않고 URL을 묻는다 — 노션에 잘못 만든 DB는 사람 손으로만 지운다. 받은 URL은 관례 문서에 적어 다음부터 안 묻는다 |
| 통합 브랜치 · 통합 PR | `track` 스킬의 값 결정 표를 따른다 |
| team 존 | 통합 브랜치가 배포되는 환경. 사람이 수정 결과를 눈으로 보는 유일한 자리다 |
| 스펙 이슈 | `fix`에서만 판정 근거로 쓰고, `setup`은 피그마 URL을 캐낼 때만 읽는다. 통합 PR 본문과 티켓 이슈의 참조에서 찾고, 없으면 트랙명·화면 이름으로 `gh issue search`. 그래도 없으면 **없는 채로 진행한다** — 스펙은 판정을 강화하는 근거지 수정의 전제가 아니다 |

scan·setup 전용 값은 대상 레포 `.qa/config.yaml`: 존 URL · 피그마 `file_key`/`page_id` 기본값 · QA 시트 URL · `storageState` 경로 · 뷰포트 · 동적 세그먼트 식별자 · 진입 상태 이름 · 종결 상태 이름 · 오라클 좌표(`oracle:` 블록 — `/oracle` 스킬이 같은 자리를 읽는다).

**scan·setup의 실행 위치는 대상 레포다.** `.qa/`·`.gitignore`·스크린샷 상대 경로가 전부 거기 기준이다. Playwright MCP는 플러그인이 등록하므로(`plugin.json`의 `mcpServers`) 어느 레포에서 켜도 `mcp__*playwright*` 도구가 뜬다. 안 뜨면 세션을 다시 켠다 — MCP는 세션 시작 때만 붙는다.

## 시트 스키마

| 프로퍼티 | 타입 | 채우는 주체 |
| --- | --- | --- |
| (title) | title | agent — 증상 요약 한 줄. 새로 만드는 시트는 이름을 `증상`으로, 기존 시트는 이름이 무엇이든 그대로 두고 거기에 증상을 쓴다 |
| 테스트 번호 | number | agent — 시트 내 최대 + 1 |
| 재현순서 | text | 사람 (scan 행은 agent가 대장 스텝을 사람 문장으로) |
| 테스트한 사람 | person | 사람 |
| 성질 | select `폴리싱` / `로직` / `미판정` | agent |
| 해결 여부 | status — 위 상태 머신 7개 | agent (`시작전`·`배포 완료`는 사람) |
| PR | url | agent |
| 비고 | text | agent — `사람 확인 필요`로 보낼 때 사유, scan 행은 `qa-key:`와 근거 |

기존 시트를 만나면 **없는 프로퍼티와 없는 status 옵션만 추가한다**(`notion-update-data-source`). status 옵션 추가는 기존 행의 값을 건드리지 않는다. status 그룹은 `작성 중`·`시작전`·`사람 확인 필요`를 to-do, `진행 중`·`리뷰`·`PR 완료`를 in-progress, `배포 완료`를 complete에 둔다 — 사람 눈을 통과하기 전은 끝난 게 아니다. `작성 중`을 to-do의 맨 앞에 둬서 노션이 새 행에 먼저 제안하게 한다.

## 용어 (scan·setup)

| 용어 | 뜻 |
| --- | --- |
| 대장 | 대상 레포 `.qa/ledger.yaml`. 화면 > 캡처 > 섹션 계층으로 도달 경로·시안 노드·셀렉터를 적은 사람 검수 자산. 앱 단위 — 트랙보다 오래 산다. 스키마는 [`references/setup.md`](references/setup.md) |
| 실물 / 시안 | team 존 스크린샷 / 피그마 노드 이미지 |
| 갈래 | 판정이 고르는 결함 종류 여덟: 여백·크기·컬러·에셋·정렬·문구·누락·잉여 |
| 지문 키 | `<화면 slug>[-<스텝>]/<섹션 slug>/<갈래>`. 시트 `비고`에 `qa-key: …`로 박혀 중복을 거른다 |
| 짝짓기 | 실물 캡처와 시안 프레임이 같은 화면인지 확인하는 일. 실행 게이트(`match_text`)와 판정의 `같은 화면인가` 두 겹 |
| 미커버 / 시안 대기 | 못 찍은 화면(대장을 손봐라) / `stale`로 건너뛴 섹션(시안을 기다려라) |

## 분기 판별

**인자 필수** — `/qa <setup|scan|collect|fix>`. 인자가 없으면 아무것도 실행하지 않고 상태만 찍는다: 시트 상태 분포 · 마지막 scan 실행 시각과 요약(`.qa/runs/`) · 대장 신선도(`figma.version`) — 그리고 어느 분기로 보이는지 한 줄 제안한다. 네 분기 모두 외부에 보이는 것(노션 행·브랜치·PR·시트)을 만들므로 감지 결과는 제안까지만 쓴다.

## agent가 하지 않는 것

기계 발견의 범위는 scan의 시안 대조 폴리싱까지다. 로직·UX 결함 발견과 판단은 사람 몫이고(플로우 검사 확장은 [#22](https://github.com/OhSeungWan/skills/issues/22)), 그 자리를 어설픈 자동화가 대신하면 품질이 내려간다. agent가 앱을 띄워 재현하는 일은 fix에서 정적 추적이 실패했을 때의 마지막 수단뿐이다 — 게이트와 예외는 [`references/fix.md`](references/fix.md).
