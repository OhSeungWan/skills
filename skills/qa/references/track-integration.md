# track-integration — 트랙 관례 레포의 결합 규칙

`track`·`oracle` 스킬 관례(통합 브랜치·통합 PR·티켓 표·노션 오라클 DB)를 쓰는 레포에서만 읽는다. 코어(setup·scan·collect)는 이 파일 없이 돈다. fix 분기는 이 관례를 전제한다 — [`fix.md`](fix.md).

## 값 결정 — 후순위 옵션

1순위는 언제나 `.qa/config.yaml`([`SKILL.md`](../SKILL.md)). 아래는 config에 값이 없을 때 트랙 관례에서 캐내는 후순위다. 캐낸 값은 config에 기록해 다음부터 안 캔다.

| 값 | 트랙에서 캐는 곳 |
| --- | --- |
| 통합 브랜치 · 통합 PR | `track` 스킬의 값 결정 표를 따른다 |
| team 존 | 존의 트랙 층 특수화 — 통합 브랜치가 배포되는 존. 트랙 QA에서 사람이 수정 결과를 눈으로 보는 유일한 자리라 config `zone:`을 이것으로 둔다 |
| QA 시트 | 트랙명·브랜치명으로 워크스페이스 검색해 후보 제시·확인 |
| 피그마 URL | 스펙 이슈에서 캐낸다 — setup의 힌트. 통합 PR 본문과 티켓 이슈의 참조에서 스펙 이슈를 찾는다 |
| scan 범위 | 통합 PR 대시보드 티켓 표에서 화면 목록을 뽑아 제시하고 확인받는다 — 트랙이 안 건드린 화면의 불일치는 이번 QA의 몫이 아니고 시트에 쌓이면 오탐 취급을 받는다 |
| 스펙 이슈 | `fix`에서만 판정 근거로 쓴다. 통합 PR 본문과 티켓 이슈의 참조에서 찾고, 없으면 트랙명·화면 이름으로 `gh issue search`. 그래도 없으면 **없는 채로 진행한다** — 스펙은 판정을 강화하는 근거지 수정의 전제가 아니다 |

## 오라클 → 정답지 파일 스냅샷

트랙 레포의 플로우 정답지 **정본**은 노션 오라클 DB(④ 화면 기대)다. setup은 오라클을 직접 분해하지 않는다 — **오라클 ④ `확정` 항목을 `.qa/flows/<트랙 slug>.yaml` 정답지 파일로 스냅샷**하고, 분해는 코어 경로([`setup.md`](setup.md))가 그 파일만 읽는다. 파일이 옛 대장 머리말 `oracle.snapshot`을 대체한다([ADR-0005](../../../.agents/adr/0005-flow-answer-key-is-single-human-confirmed-source.md)).

- 좌표는 config `oracle:` 블록 — `/oracle` 스킬이 같은 자리를 읽는다. SQL 쿼터에 막히면 view 모드 폴백도 같다.
- 스냅샷은 setup에서 1회 — scan은 오라클을 부르지 않는다. 매 실행이 정답지 원본을 부르지 않는 것은 피그마 캐시와 같은 원칙이다.
- 항목은 4칸(id·문장·상태·출처=오라클 항목 URL) 그대로 옮긴다. 파일은 파생물 — 오라클과 어긋나면 오라클이 이기고, 갱신은 `/oracle`이 한다.

## 오라클 "시안과 다름" stale 초안

setup의 같은 1회 읽기에서 ④ 화면 기대 항목 중 **"시안과 다름"이 명시된 것**을 골라, 항목이 가리키는 시안 프레임·노드가 대장의 어느 캡처·섹션에 물려 있는지 맞춘다. 물린 섹션이 있으면 `stale: <항목 ID> — <사유>` **초안**을 setup의 사람 제안 목록에 올리고, 항목의 프레임이 대장에 안 쓰였거나 화면 자체가 없으면 매핑 없음으로 리포트에만 남긴다. 1차 scan에서 화면 하나가 통째로 짝짓기 거부된 원인이 정확히 이 부류다 — 시안에만 있는 요소를 실물 결함으로 읽는다.

초안은 자동 기입이 아니다 — `stale`은 사람 값이다. 제안에는 대안을 붙인다: `stale`은 섹션 판정 전체를 죽이므로 차이가 요소 하나뿐이면 `ignore` 한 줄이 나을 수 있다. 어느 쪽이든 판정 프롬프트에는 주입하지 않는다 — 시야를 넓히면 정밀도가 떨어진다.

## 오탐의 정답 신호와 오라클

scan 오탐 행의 `버그 아님` 판정이 "구현이 맞고 정답지가 틀림"이면 `/oracle`로 오라클을 먼저 고친다 — 안 고치면 다음 스냅샷·scan이 같은 항목을 또 버그로 보고한다.
