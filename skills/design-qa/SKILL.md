# design-qa

`qa` 루프의 **빠진 첫 칸**이다. 지금 `collect`는 사람이 눈으로 찾아 타이핑하는 자리이고, 이 스킬은 그 자리를 기계가 채운다. 병목이 QA 시트이므로 사람이 열었을 때 이미 차 있어야 한다.

**정밀도가 재현율보다 중요하다.** 아래 결정 대부분은 "덜 찾더라도 틀린 걸 안 올린다"를 사는 값이다. 오탐이 섞인 시트는 한 번만 나와도 사람이 이 도구를 다시 안 켠다.

이 스킬이 하지 않는 것:

- **QA 시트를 만들지 않는다.** 없으면 멈추고 `/qa collect`로 안내한다 — 첫 삽은 `qa`의 일이다.
- **수정·PR·상태 전이를 하지 않는다.** 행을 하나 만들고 끝이다. 그 뒤는 `qa fix`가 돈다.
- **코드를 짚지 않는다.** 그래서 `성질`은 전부 `폴리싱` 고정이다. 로직 여부를 가를 근거 자체가 없다.
- **머지를 막지 않는다.** PR 게이트가 아니라 사람 QA 직전 배치다.

## 값 결정

`skills/qa/SKILL.md`의 **값 결정 표 4줄**과 **시트 스키마**를 그대로 물려받는다 — QA 시트 · 통합 브랜치/통합 PR · team 존 · 스펙 이슈. 여기 다시 적지 않는다.

물려받지 않는 줄이 하나 있다: **시트 부모 페이지**(= 시트 생성). 스펙 이슈는 `setup`에서만 읽는다 — 피그마 URL을 캐내는 자리다.

design-qa 전용 값은 대상 레포 `.design-qa/config.yaml`에 산다: 존 URL · 피그마 `file_key`/`page_id` 기본값 · QA 시트 URL · `storageState` 경로 · 뷰포트 · 동적 세그먼트 식별자 · 진입 상태 이름.

## 분기 판별

인자가 `setup`이면 [`references/setup.md`](references/setup.md)로 간다. 화면 대장이 없거나, 시안이 바뀌었거나(`figma.version` 불일치), `unpaired`·`unreached` 줄을 손봐야 할 때다.

인자가 `scan`이거나 없으면 아래로 간다. `.design-qa/ledger.yaml`이 없으면 `setup`으로 안내하고 멈춘다.

## 전제 확인 — scan 앞머리에서 한 번

순서대로. 하나라도 못 넘기면 멈추고 무엇이 없는지 보고한다.

1. **`.design-qa/ledger.yaml`과 `config.yaml`이 있는가.** 없으면 `setup`.
2. **QA 시트가 있는가.** 없으면 `/qa collect`로 안내하고 멈춘다.
3. **진입 상태 이름을 찾는다.** 시트 스키마를 1회 읽어 `해결 여부`의 타입(`select`일 수도 `status`일 수도 있다)과 옵션 목록을 얻고, **공백을 무시해** `사람 확인 필요`를 찾는다(`사람확인필요`로 비교). 못 찾으면 지어내지 않고 옵션 목록을 사람에게 보여 주고 고르게 해 `config.yaml`에 적는다. 상태 이름을 하드코딩하지 않는다.
4. **title 프로퍼티를 타입으로 찾는다.** 이름이 `증상`이 아닌 시트가 실재한다(`이미지 첨부`). 타입이 `title`인 프로퍼티에 증상 한 줄을 쓴다.
5. **지문 키를 통째로 1회 조회한다.** `WHERE "비고" LIKE '%qa-key: %'` 한 번으로 기존 키를 다 받아 클라이언트에서 대조한다. 실행당 쿼리는 이것과 채번 둘뿐이다.
6. **범위를 정한다.** 인자로 받은 화면 slug 목록이 1순위, 없으면 통합 PR 대시보드 티켓 표에서 화면을 뽑아 제시하고 확인받는다(티켓이 화면 단위 vertical slice라 축이 맞는다). 전량은 `--all`이다 — 트랙이 건드리지 않은 화면의 불일치는 이번 QA의 몫이 아니고, 시트에 쌓이면 오탐 취급을 받는다.
7. **예산을 찍고 확인받는다.** 화면 N개 · 섹션 M개 · 예상 K분(목표는 화면 10개당 15분). 시간으로 자르는 게이트는 두지 않는다 — 잘린 화면이 조용한 미판정으로 남는다.

## 화면 하나를 도는 순서

`ledger.yaml`의 캡처 한 줄이 한 바퀴다.

1. **`requires`와 `stale`을 확인한다.** `requires`에 나열된 `config.yaml` 키 중 하나라도 비어 있으면 이 화면을 건너뛰고 **미커버**로 센다.

   섹션에 `stale`이 적혀 있으면 **그 섹션만** 촬영도 판정도 건너뛰고 **시안 대기**로 센다. 화면의 나머지 섹션은 정상으로 돈다 — 판정에 안 들어간 섹션은 거부할 주체가 없으므로 9번의 화면 통째 폐기 규칙과 부딪히지 않는다.

   이 예외가 안전한 이유는 `stale`이 **사람이 검수해 손으로 적는 값**이라는 것뿐이다. 실행이 "이 섹션만 낡았다"를 추론하는 순간 폐기 규칙이 무의미해진다 — 그 추론이 원리적으로 안 된다는 게 규칙이 사는 이유다. 대장은 원래 사람 검수 자산이고 `stale`은 정확히 그 자리에 산다.
2. **도달한다.** `path`로 이동하고 `before` 스텝을 순서대로 실행한다 — `clickText`(정확히 일치하는 문구) · `fillPlaceholder` · `scrollToText`. 화면의 `forbidden` 목록에 있는 문구는 어떤 경우에도 `clickText` 하지 않는다. 실제 주문을 만드는 버튼이 거기 있다.
3. **`arrival_text`를 확인한다.** 없으면 조작이 막혔을 때 직전 화면을 그대로 다시 찍고 "차이 없음"으로 통과한다 — 도달 실패가 조용한 성공으로 둔갑한다. 못 찾으면 이 캡처를 건너뛰고 **미커버**로 센다.

   첫 화면에서 실패했다면 세션 쪽을 의심한다. **실패 모양이 셋이고 셋 다 "시안과 아주 다름"으로 보인다**: 로그인 화면(세션 미주입·만료) · `Network Error` 한 줄(앱 셸은 정상 렌더되므로 가장 위험하다 — `--grant-permissions local-network-access` 누락) · 파일이 안 생김(상대 `filename`은 서버 cwd에 떨어진다). 세션 갱신은 `.agents/design-qa/design-qa-session-wizard.sh`.
4. **프라이밍 스크롤 1회.** 문서 끝까지 훑고 원위치로 복귀한다. 요소 스크린샷은 뷰포트 밖까지 한 장으로 굽는데, 화면 밖에 있던 부분은 lazy-load 이미지가 미도착이거나 진입 애니메이션이 안 돌았을 수 있다. **그 실패는 `흐릿함`·`누락`으로 나타난다** — 이 도구가 겨냥한 부류를 그대로 오염시키고, 사람도 스크린샷만 보고는 판별할 수 없다.
5. **짝짓기 게이트를 통과시킨다.** 캡처의 `match_text` 중 실물 DOM에 나타나는 것이 **2개 미만이면** 이 캡처를 건너뛰고 **짝짓기 실패**로 센다. 대조는 프라이밍 스크롤 뒤의 DOM으로 하고(setup의 도달 검증도 같은 시점을 쓴다), 공백·개행을 없앤 뒤 포함 비교하며, `match_text`는 앞 12자로 잘라 비교한다(실물 말줄임 대응).

   **여기서 대장을 고치지 않는다.** 실패 원인이 시안 변경인지 코드 변경인지 실행에는 구분할 근거가 없고, 대장은 사람 검수를 거친 자산이다. 대장 수정은 `setup`의 일이다.
6. **섹션마다 실물을 찍는다.** 숨김과 가드를 **한 `evaluate` 호출**로 함께 돌린다 — 대상 섹션 **밖**의 `fixed`/`sticky` 요소에 `visibility: hidden`을 `!important`로 주고(`display: none`은 sticky의 자리를 접어 레이아웃을 밀어낸다), 같은 호출에서 대상 박스와 겹치는 잔여 고정 요소 수를 세어 돌려받는다. 배관은 [`references/setup.md`](references/setup.md)에 있다.

   **잔여가 0이 아니면 그 섹션을 판정에 보내지 않고 리포트에 표기한다.** 숨김이 조용히 실패하면 가림이 이미지에 구워지고, 그건 실측된 **가장 그럴듯한 오탐**이다(헤더에 덮여 잘린 원을 "찌그러짐, 확신도 높음"으로 읽었다).

   숨김을 섹션 밖으로만 한정하는 이유는 섹션이 품은 sticky가 시안에 그려져 있을 수 있어서다 — 숨기면 `누락` 오탐이 된다.

   촬영은 `browser_take_screenshot`에 섹션의 `selector`를 `target`으로, `scale: 'css'`로 준다. `capture: viewport`인 섹션만 뷰포트 한 장으로 후퇴한다(숨김은 그대로 적용). `hide_fixed: false`인 섹션(헤더·탭바)은 숨김 없이 찍는다.
7. **시안을 가져와 실물과 같은 좌표계로 맞춘다.** `.design-qa/cache/<file_key>/<figma.version>/<node_id>.png`에 파일이 있으면 그걸 쓴다 — 그게 캐시 로직의 전부다. 없으면 `get_screenshot`에 `maxDimension: 1568`을 주고, 돌아온 단명 URL을 curl로 그 경로에 떨군다. 인라인 base64는 쓰지 않는다(캐시가 원리적으로 불가능하고, `qa fix` 뒤 재실행이 주 사용 패턴이다).

   **떨군 뒤 자연 css 폭으로 되돌려 캐시에 굳힌다** — `sips --resampleWidth <original_width>`, 그 값은 `get_screenshot` 응답의 `original_width`가 준다. 피그마는 노드를 2배로 구워 주고 `maxDimension`이 섹션 높이에 따라 다르게 물리므로, 안 맞추면 짝마다 배율이 1.0~2.0 사이로 흔들린다.

   실물은 `scale: 'css'`라 DPR 1이고 그게 이 도구의 해상도 천장이다 — 시안만 2배로 남겨 둬도 대조에 쓸 정보는 안 늘고 판정이 **어느 쪽 픽셀을 읽었는지 모르는 수치**를 낸다. 실측이 있다: `room-bar`가 `높이 46px(시안 62px)`을 냈는데 시안 노드 자연 크기는 390x104고 캐시는 780x208이라 62가 어느 좌표계인지 판별할 근거가 없었다. 맞추고 나면 **두 이미지 모두 이미지 px = css px**이 되어 8번의 `근거` 필드가 환산 없이 성립한다.

   캐시 무효화는 디렉터리 이름이 전부다. 지우는 코드를 짜지 않는다 — `figma.version`이 바뀌면 옛 디렉터리는 자연히 안 읽히고, 사람이 폴더째 지운다.
8. **섹션당 서브에이전트 하나로 판정한다.** 입력은 **이미지 2장 고정**(실물 · 시안)이고 맥락은 텍스트로만 준다 — 화면 이름 · 섹션 이름 · 그 섹션의 `ignore` 목록. 화면 전체 샷을 곁들이면 섹션 크롭으로 좁혀 놓은 효과가 되돌아간다. 문안은 [`references/judge.md`](references/judge.md)를 그대로 쓴다.

   **`degraded: true` 섹션은 두 이미지를 같은 비율로 세로 분할해 여러 쌍으로 나눠 판정한다.** 한 장이 css 1500px을 넘지 않도록 등분하고 **인접한 장끼리 15% 겹치게** 자른다(`sips --cropToHeightWidth`). 7번이 두 이미지를 같은 좌표계로 맞춰 놓았으므로 같은 비율 자르기가 그 위에서 공짜로 성립한다 — 노드 구조를 안 타므로 자식으로 못 내려가는 인스턴스에서도 돈다. 겹침은 경계가 카드 중간을 지나 반쪽만 보인 것을 `누락`으로 읽는 새 오탐 경로를 막는다. 겹침 구간의 중복 판정은 지문 키가 갈래 단위라 9번에서 저절로 걸러진다. **지문 키에 장 번호를 붙이지 않는다** — 자른 건 판정 편의고 섹션은 여전히 하나다. 분할한 장을 판정에 넘길 때는 **더 큰 섹션을 잘라낸 한 장이라고 알려 준다** — 계약이 잘린 가장자리를 `누락`·`잉여`로 적지 않게 하는 조건이다.
9. **판정을 거른다.** 순서대로:
   - `같은 화면인가: 아니오`가 **한 섹션이라도** 나오면 **그 화면 전체를 버리고** **짝짓기 거부**로 센다. 다수결로 쓰지 않는다 — 거부가 3/4였는데도 남은 하나가 그럴듯한 가짜 3건을 낸 실측이 있다.

     버려지는 판정이 진짜여도 버린다. 실측: `chat-room`에서 헤더 시안이 결정보다 낡아 거부가 났고, 함께 버려진 `room-bar` 판정은 `높이 46px(시안 62px)`까지 잰 진짜였다. 그래도 그 62px은 **폐기된 프레임 기준값**이라 시트에 올랐으면 개발자가 죽은 기준에 맞춰 고쳤을 것이다. 그럴듯하고 실행 가능한 오탐이 그냥 오탐보다 나쁘다.

     그리고 **대장의 그 화면 `status`를 `unpaired`로, `confidence`를 `guessed`로 강등한다.** 실행이 대장을 고치는 유일한 자리다 — 정보를 지우는 방향이 아니라 사람에게 보내는 방향이라서 허용된다. 다음 `scan`은 그 화면을 안 찍고 `setup`이 받는다.
   - `확신도: 낮음`은 시트에 넣지 않고 **증상 한 줄까지** 리포트에 뿌린다. 개수만 남기면 오탐률을 나중에 재구성할 수 없다.
   - `대상: 시안`은 시트에 넣지 않고 리포트에 모은다. 시트는 개발자가 고칠 것만 쌓여야 큐로 쓸모가 있다.
   - 지문 키 `<화면 slug>[-<스텝>]/<섹션 slug>/<갈래>`가 기존 키와 겹치면 버린다. `LIKE`는 부분 문자열이라 **키에 끝 경계를 준다** — 안 주면 `…/spacing`이 `…/spacing-2`를 잡아먹는다.
10. **행을 만든다.** 남은 항목마다 하나씩:
    - `테스트 번호`는 시트 내 MAX+1. 동시 실행이면 에러 없이 중복이 생기므로 만들고 나서 중복을 감지해 보고한다(트리거가 사람 슬래시 커맨드라 겹칠 확률은 낮다).
    - title(타입으로 찾은 것)에 **증상 한 줄**. 리치 텍스트라 인라인 마크다운이 해석된다 — **서식 문자를 쓰지 않는다**(`[홈]`이 아니라 `홈 > 히어로`). 번호도 지문 키도 넣지 않는다.
    - `성질`은 `폴리싱`, `해결 여부`는 전제 확인에서 찾은 진입 상태(`사람 확인 필요`).
    - `재현순서`는 VLM이 쓰지 않는다 — 대장의 `before` 스텝을 사람이 읽을 문장으로 옮긴다.
    - `비고` 첫 줄에 `자동 생성 (design-qa)`, 둘째 줄에 `qa-key: …` 그리고 갈래 · 대상 · 확신도, 그다음 줄에 판정이 준 **`근거`**(위치 · 실물값 · 시안값). 값을 `측정 불가`로 답한 항목은 그대로 적는다 — 지우면 리포트가 남용을 못 센다.
    - 계약이 **"이 섹션 전체가 시안과 어긋남" 1건으로 접은** 판정이면, 접힌 개별 항목을 행 **본문에 체크박스 한 줄씩** 넣는다. 접기 규칙 자체는 유지한다(어긋난 섹션 하나가 시트에 열몇 행을 쏟는 걸 막는 값이 여전히 유효하다) — 문제는 접힌 뒤 **추적이 죽는다**는 것뿐이었다. 비고에 산문으로 적으면 고치는 사람이 개별 항목을 못 닫아 행이 영영 안 닫힌다.
    - `테스트한 사람`은 **비워 둔다.** 봇 계정이 없어 사람 id를 넣으면 그 사람이 QA한 것처럼 보이는 거짓 기록이 된다.
    - 스크린샷 2장을 행의 **페이지 본문 이미지 블록**으로 넣는다 — `create-file-upload` → 받은 URL로 멀티파트 POST → 응답의 `suggested_markdown`. `files` 속성에 꽂는 건 실패한다. **업로드는 1회용이고 URL 수명이 약 10분**이라 판정 직후에 올려 바로 행을 만든다.

## 리포트

터미널 출력뿐이다. 영구 저장은 하지 않는다(오탐률 측정 자리가 아직 안 정해졌다).

일곱 숫자를 찍고, **각 항목의 증상 한 줄까지 함께 뿌린다**:

| 숫자 | 뜻 | 늘면 무엇을 하나 |
| --- | --- | --- |
| 무결 판정 N | 판정이 차이 없다고 답한 섹션 | 아무것도. **없으면 안 된다** — 이 칸이 없으면 "봤고 멀쩡했다"와 "안 봤다"가 구분이 안 된다 |
| 낮은 확신 N | 시트에 안 넣고 버린 판정 | 오탐률 판단의 원천 데이터 |
| 미커버 N | `requires` 미충족 · 도달 실패 · `unreached`/`blocked`/`unpaired` | 대장을 손본다(`setup`) |
| 시안 대기 N | `stale`이 적혀 건너뛴 섹션 | 아무것도. **늘어나는 건 나쁜 신호가 아니라 구현이 시안보다 앞서 있다는 신호다** |
| 시안 결함 N | `대상: 시안` | 디자이너에게 가는 것 |
| 짝짓기 실패 N | 실행 게이트가 막은 캡처 | **시안이 바뀐 신호** — `setup`을 돌린다 |
| 짝짓기 거부 N | 판정이 거부해 강등된 화면 | **게이트가 뚫린 신호** — `setup`이 받아 `틀린 짝`인지 `낡은 시안`인지 사람과 가른다 |

뒤 둘을 합치지 않는다. 사람이 할 일이 다르다. **`미커버`와 `시안 대기`도 합치지 않는다** — 미커버는 `대장을 손봐라`고 시안 대기는 `시안을 기다려라`다.

`무결 판정`을 시트에 올리지 않는다. 리포트의 숫자 하나로 충분하고, 결함 없는 행은 QA 큐를 희석할 뿐이다.

여기에 **분할 판정 N개**(`degraded: true`라 세로로 나눠 판정한 섹션) · **가림 잔여 N개**(6번 가드에 걸린 섹션) · **`측정 불가` N개**(근거를 못 댄 항목)를 덧붙인다. 조용한 누락은 병목을 줄이는 척하며 늘린다 — 열화는 표기가 붙는 한 허용되고, 침묵은 허용되지 않는다.

## 승격

두 옵션이 오탐률 데이터를 기다린다. 지금은 둘 다 꺼져 있다.

- **트리거 자동화** — 배포 훅. 지금은 사람이 슬래시 커맨드로만 켠다.
- **진입 상태 직행** — `사람 확인 필요` 대신 `시작 전`으로 넣어 `qa fix`의 큐에 곧장 올리기. 오탐이 섞인 행이 그 큐에 들어가면 `fix`가 정적 추적으로 "시안과 다름"을 짚으려다 `원인 미특정`으로 되던져 왕복만 한다.
