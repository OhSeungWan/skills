# grind

`track`이 정한 3층 브랜치 라이프사이클을 **사람 없이** 돌린다. 티켓 1장 = 새 `claude -p` 프로세스 1개 = 전용 워크트리 1개.

**이 스킬의 존재 이유는 컨텍스트다.** 같은 세션에서 티켓을 이어 하면(`/loop` 포함) 티켓 N장의 맥락이 한 자리에 쌓여 뒤로 갈수록 판단이 나빠진다. 새 프로세스는 컨텍스트가 비어 있고, 셸 스크립트는 컨텍스트가 아예 없다.

**성립 근거는 통합 PR 본문이 이미 상태 저장소라는 것이다.** `/track merged`가 티켓 표에 상태와 머지 SHA를 쓴다. 그래서 새 프로세스는 통합 PR 하나만 읽으면 트랙이 어디까지 왔는지 안다. 인수인계 파일을 따로 만들지 않는다.

배관은 [`scripts/run-tickets.sh`](scripts/run-tickets.sh)에 있다. 이 스킬은 **그 스크립트를 언제 어떻게 부르고, 무엇을 먼저 확인하고, 실패를 어떻게 읽는지**를 정한다.

## 이 스킬이 하지 않는 것

- **티켓을 쪼개지 않는다.** 티켓 이슈가 이미 있어야 한다. 없으면 스펙 분할이 선행이다.
- **트랙을 열지 않는다.** 통합 브랜치·통합 PR은 `/track start`의 일이다.
- **통합 PR을 최종 base로 머지하지 않는다.** 티켓 PR을 통합 브랜치로 넣는 데서 멈춘다. `develop`으로 나가는 판단은 사람 몫이다.
- **티켓 PR을 사람에게 보여주지 않는다.** 리뷰는 나중에 통합 PR에서 한 번에 한다는 전제 위에 서 있다. 그 전제를 못 받아들이면 이 스킬을 쓰면 안 된다.
- **블로커를 경중으로 나누지 않는다.** 막히면 전부 정지다. 무인 인스턴스가 "이건 경미하니 우회"를 스스로 판정하면 티켓 범위가 조용히 넓어진다.
- **후속 티켓을 만들지 않는다.** 범위 밖 작업이 발견되면 통합 PR 「열린 질문」에 남기고 넘어간다. 티켓화는 사람 몫이다.
- **병렬로 돌지 않는다.** 아래 함정 참조.

## 전제 — 하나라도 없으면 멈추고 무엇이 없는지 보고한다

1. **`/track` 규약으로 도는 트랙인가.** 통합 브랜치가 있고 통합 PR이 열려 있어야 한다. 통합 PR 본문에 대시보드 5블록(티켓 표·**트랙 결정**·리뷰 포인트·배포 전 사람 몫·열린 질문)이 있어야 한다 — 「트랙 결정」이 없으면 `/track` 규약대로 먼저 만든다.
2. **티켓이 GitHub 이슈인가.** 실패 판정이 이슈 close 실측이라 이슈가 없으면 게이트가 없다.
3. **`orca` · `gh` · `jq`가 있는가.** `orca status`가 응답해야 한다(아니면 `orca open`).
4. **러너 스크립트가 제자리에 있는가.** `<git-common-dir>/matt-context/run-tickets.sh`. 없으면 스킬 저장소의 `scripts/run-tickets.sh`를 거기로 복사한다 — 그 자리에 두면 repo마다 갱신할 것이 없다.
5. **사용자가 무인 실행을 승인했는가.** 스크립트는 `--dangerously-skip-permissions`로 돌고 티켓 PR을 **자동 머지**한다. 되돌리기는 통합 브랜치 reset 범위 안이지만, 이건 매번 새로 받는 승인이 아니라 트랙 착수 시 한 번 받는 승인이다.

## 값 결정

전부 현재 체크아웃에서 감지한다 — 트랙별 설정 파일이 없다.

| 값 | 결정 방법 |
| --- | --- |
| repo | `gh repo view --json nameWithOwner` |
| 통합 브랜치 | 현재 HEAD. **그래서 통합 브랜치를 체크아웃한 상태에서 불러야 한다** |
| 통합 PR | 통합 브랜치를 head로 하는 열린 PR. 없으면 중단 |
| 티켓 브랜치 번호 | PR head ref(머지된 것 포함) ∪ origin 브랜치 ∪ 로컬 브랜치에서 끝의 숫자 최대 + 1 |
| 검증 게이트 | `<git-common-dir>/matt-context/repo-gates.md`. 없으면 에이전트가 알아내서 거기 적는다 |
| 주입점 | 통합 PR 코멘트 중 리액션이 안 붙은 것 (아래 「주입점」) |

## 착수 전 — 열린 결정을 먼저 닫는다

**이 단계를 건너뛰면 러너가 중간에 멈춘다.** 돌릴 티켓들의 이슈 코멘트를 훑어 **사람 판단을 요구하는 선택지**가 남아 있는지 본다. 앞 티켓이 뒤 티켓에 숙제를 넘기는 일이 실제로 일어난다(실측: 티켓 A가 티켓 B에 (a)/(b) 선택지를 코멘트로 남겼다).

닫는 방법은 둘이다:

- **사람에게 묻는다** — 어느 쪽으로 갈지 정말 갈리는 결정일 때.
- **판정하고 근거를 적는다** — 한쪽이 명백히 트랙의 기존 원칙과 같은 모양일 때. 판정했으면 **반드시 사용자에게 무엇을 어느 쪽으로 정했는지 한 줄로 알린다.** 조용히 정하지 않는다.

어느 쪽이든 결론은 **통합 PR 본문 「트랙 결정」 절**에 **사실로** 적는다. 지시가 아니라 사실이다("~하지 마"가 아니라 "계약이 X로 확정됐다").

## 절차

1. 통합 브랜치 체크아웃인지 확인하고 `git pull --ff-only`로 앞 티켓 머지를 당겨온다.
2. 위 「착수 전」을 돈다.
3. `<git-common-dir>/matt-context/run-tickets.sh <티켓번호...>`를 **백그라운드로** 띄운다.
4. 진행상황을 본다 — Orca 보드의 워크트리 상태와 스크립트 stdout.
5. 끝나면 결과를 읽고 사용자에게 보고한다. 러너가 남긴 「주의」·「천장」·미달 AC를 **전부 옮긴다.** 요약하면서 지우지 않는다.

여러 장을 인자로 주면 순차로 돈다. 한 장이 실패하면 거기서 멈추고 뒤는 안 돈다.

## 진행상황을 보는 자리

- **Orca 보드** — 워크트리 상태가 `in-progress`(구현중) → `in-review`(리뷰중) → `completed`(구현완료). 스크립트가 `in-progress`와 `completed`를, 에이전트가 티켓 PR 개설 직후 `in-review`를 찍는다. `completed`를 스크립트가 쥐는 이유는 에이전트의 자기신고보다 이슈 close 실측이 믿을 만해서다.
- **stdout** — 에이전트가 찍는 `## 단계명` 마커와 result 한 줄만. **툴 이름은 안 나온다** — stdout은 오케스트레이터 세션의 컨텍스트를 먹는 자리라 의도적으로 좁혔다. 툴 인자까지 필요하면 원본 `.jsonl`을 본다.
- **원본** — `<git-common-dir>/matt-context/ticket-runs/<통합브랜치>/ticket-<n>.jsonl`. stderr는 `.err`.

## 실패를 읽는 법

**`claude`의 exit code는 작업 성공과 무관하다.** 유일한 판정은 **티켓 이슈가 CLOSED인가**다. `/track merged`의 1항이 이슈를 닫으므로, 프롬프트는 에이전트에게 "막히면 이슈를 닫지 마라"를 박아 둔다.

실패하면 스크립트가 거기서 멈추고 워크트리를 남긴다. 사람이 볼 것은 `.jsonl`의 마지막 `##` 마커와 `.err`다. `.jsonl`은 **순수 JSON이 아니다** — 위 함정대로 비-JSON 줄이 섞이므로 `jq`로 읽을 땐 `-R`과 `fromjson?`를 쓴다.

**재개 전에 실측할 것 둘**: ⑴ 고아 `claude` 프로세스가 아직 도는가 — 있으면 죽인다. ⑵ 워크트리에 커밋이 이미 있는가(`git log`·`git status`) — 있으면 구현을 다시 시키지 말고 남은 단계만 이어받는다.

## 티켓이 가리키는 것 — 참조 문서

티켓 이슈가 정본이지만, 계약·응답 스펙은 보통 이슈가 링크한 외부 문서(BE가 쓴 노션 등)에 있다. 인스턴스는 **그 링크를 따라가 읽는다 — 1단만.** 2단 이상은 무인 실행에서 토큰이 통제 불능으로 늘고, 노션 문서는 서로 링크가 얽혀 있다.

**이건 주입점이 아니다.** 매 티켓이 새로 읽으므로 항상 최신이고, 그래서 아래 노트로 옮기지 않는다 — 옮기면 낡은 사본이 생긴다. 대신 **못 읽었을 때가 위험하다**(아래 함정).

## 주입점 — 통합 PR 하나가 노트다

별도 노트 파일이 없다. **러너가 도는 중에 계약·기획이 바뀌면 통합 PR에 코멘트 한 줄을 던진다.** 3단으로 돈다:

| 단계 | 어디 | 누가 |
| --- | --- | --- |
| 입력 | 통합 PR **코멘트** (append-only) | 사람 |
| 읽기 | **리액션이 안 붙은 코멘트만** — 티켓 시작 시 · **티켓 PR 본문 작성 직전** 두 번 | 인스턴스 |
| 소진 | 반영하면 `+1`, 후속으로 미루면 `eyes` 리액션 | 인스턴스 |
| 승격 | 트랙 전체에 계속 유효한 사실이면 본문 **「트랙 결정」** 절에 한 줄 | 인스턴스 |

```
gh api repos/<repo>/issues/<통합PR>/comments --paginate \
  --jq '.[] | select((.reactions["+1"] // 0) == 0 and (.reactions.eyes // 0) == 0)'
```

**커서 파일을 두지 않는 이유**는 소진 상태가 데이터에 붙어 살아야 워크트리를 지워도 남고, PR UI에서 사람이 무엇이 반영됐는지 눈으로 보기 때문이다. `gh api` 한 방이 코멘트와 리액션 카운트를 같이 준다.

**승격이 필요한 이유**는 리액션이 "이 티켓이 처리했다"만 뜻하기 때문이다. 그 결정은 뒤 티켓도 알아야 하는데, 소진된 코멘트는 다시 안 읽힌다. 그래서 계속 유효한 사실만 본문으로 올라가고 본문은 짧게 유지된다 — 티켓 10장 뒤에도 인스턴스가 읽는 양이 안 늘어난다.

**Note에 안 들어가는 것**: 재계산 가능한 것 전부. 티켓 이슈, 이슈가 가리키는 노션 계약·응답 스펙, 통합 PR 본문 — 매 티켓이 새로 읽으니 옮기면 낡은 사본만 생긴다. Note에 들어갈 자격이 있는 건 **어디에도 안 적힌 것**뿐이다 — 사람의 판정, 티켓 사이에 확정된 계약, "이 선택지는 (a)로 간다" 류.

**두 번째 읽기 지점의 3분기.** 구현하는 동안 새로 붙은 코멘트는 셋 중 하나다: 이번 PR 코드를 틀린 것으로 만들면 **중단**, 범위 밖 추가 작업이면 `eyes` + 본문 「열린 질문」 한 줄 남기고 **진행**, 애매하면 **중단**.

## 파일 2종 — 전부 `<git-common-dir>/matt-context/` 밑

| 파일 | 누가 쓰나 | 언제 읽히나 |
| --- | --- | --- |
| `repo-gates.md` | 첫 티켓이 발견해서 쓴다 | 매 티켓 프롬프트에 통째로 인라인 |
| `ticket-runs/<통합>/` | 스크립트 | 사람이 사후에 |

배관 자체의 자가검사는 [`scripts/self-check.sh`](scripts/self-check.sh)다 — 미소진 필터와 렌더 파이프라인 둘 다 CI가 안 돌리는 자리(프롬프트 문자열 안·파이프라인 안)에 살아서 여기서 한 번 돈다. 스크립트를 고쳤으면 이걸 돌린다.

`repo-gates.md`가 이 스크립트를 **repo 무관하게** 만드는 장치다. 새 repo의 첫 티켓은 `package.json`과 CI 워크플로를 읽어 실질 게이트를 스스로 찾고 그 사실을 여기 적는다. 둘째 티켓부터 공짜로 받는다.

## 함정 — 전부 실측

- **`/loop`로는 안 된다.** 같은 세션에 프롬프트만 다시 넣는 도구라 컨텍스트가 쌓인다. 이 스킬이 존재하는 이유가 그것이다.
- **`claude -p` 프로세스는 `claude agents --json`에 안 뜬다.** 그래서 `SendMessage`로 못 닿는다. 실시간 주입이 정말 필요하면 `--input-format stream-json`으로 stdin을 열어야 하는데 FIFO와 프로토콜이 붙는다. 대부분은 통합 PR 코멘트의 두 읽기 지점으로 충분하다 — 계약 변경은 보통 티켓 사이에 도착한다.
- **`--output-format text`는 끝날 때까지 무음이다.** 로그 파일이 완료 전까지 빈다. `stream-json --verbose`가 필요한 이유.
- **`stream-json` stdout에 비-JSON 줄이 섞인다.** MCP 경고가 같은 stdout으로 샌다(실측: `Client.listTools() called but server does not advertise tools capability`). 렌더러를 순진하게 `jq -r`로 걸면 그 줄에서 죽고, **EPIPE가 `tee`를 거쳐 `claude`까지 올라가 티켓이 통째로 끊긴다**(실측: exit 144, 티켓 #1707). 그래서 렌더는 `jq -rR 'fromjson? // empty | …'`로 비-JSON을 건너뛰고, 그래도 죽으면 `|| cat >/dev/null`이 남은 stdin을 드레인한다. **렌더는 곁다리고 원본은 `.jsonl`에 이미 있다 — 곁다리가 본체를 죽이면 안 된다.**
- **끊긴 티켓의 작업은 대개 안 날아간다.** 러너가 죽어도 `claude` 자식이 고아로 남아 커밋까지 마치는 경우가 있다(실측: #1707이 `d92033ba`로 커밋 완료, 워크트리 clean). 재개 전에 **고아 프로세스와 워크트리 상태를 먼저 실측한다** — 커밋이 이미 있으면 구현 단계를 다시 돌리지 말고 검증·PR·머지만 이어받는다.
- **실행 중인 스크립트를 in-place로 고치지 마라.** bash가 파일을 이어 읽어서 실행이 깨진다. `.next`로 써두고 판이 끝난 뒤 `mv`한다.
- **orca가 브랜치명을 제 방식대로 짓는다.** 사용자 프리픽스를 붙이고 `/`를 `-`로 바꾼다(실측: 원한 `feature/X-integration-7` → 실제 `OhSeungWan/feature-X-integration-7`). 그래서 번호 계산은 접두사로 매칭하지 않고 **끝의 숫자만** 뽑는다.
- **티켓 브랜치는 머지 시 삭제된다.** `git ls-remote`로 세면 origin에 안 남아 번호가 1로 되돌아간다. PR head ref로 세야 하고, 아직 push 안 된 진행 중 티켓 때문에 **로컬 브랜치도** 세야 한다(공용 git dir라 다른 워크트리 것도 보인다).
- **`orca.yaml`이 없으면 setup hook이 안 돌아 새 워크트리에 의존성이 없다.** 스크립트가 `node_modules` 심링크를 건다. 그런데 **실행 도중 사라진 실측이 있다** — 타입체크가 모듈을 통째로 못 찾으면 재설치하지 말고 다시 링크한다.
- **워크트리 없이 돌리면 메인 체크아웃과 파일이 충돌한다.** 첫 판을 통합 브랜치 체크아웃에서 직접 돌렸더니 사람도 에이전트도 같은 파일을 건드리는 상태가 됐다.
- **린터가 무연산으로 통과할 수 있다.** 설정이 대상 확장자에 안 걸려 있어도 exit 0이 나온다(실측: ESLint가 `.ts`/`.tsx`를 전부 `File ignored`로 넘기고 통과). "통과했다"를 "검사했다"로 읽지 않도록 `repo-gates.md`에 사실을 적어 둔다.
- **CI에 상시 red인 잡이 있을 수 있다.** 그것 하나만 red일 때 진행할지 말지는 트랙마다 다르므로 `repo-gates.md`에 적는다. 안 적으면 에이전트가 매번 그 앞에서 멈춘다.
- **링크된 문서를 못 읽으면 조용히 추측한다.** 무인 인스턴스의 기본 실패 모드다. 노션 MCP 토큰이 만료되면 재인증이 대화형이라 헤드리스에서는 못 붙는다(`~/.claude/mcp-needs-auth-cache.json`에 올라간다). 그래서 프롬프트가 "못 읽었으면 그 사실을 출력하고, 그 링크가 계약이면 중단"을 박아 둔다. 0건을 "변경 없음"으로 읽으면 안 된다.
- **`claude.ai *` 접두사 MCP는 헤드리스에 안 붙는다.** 대화형 인증이라서다. `plugin:*` 스코프(예: `plugin:Notion:notion`, `plugin:slack:slack`)는 붙는다 — `claude mcp list`로 실측한다.
- **리액션은 이진값이다.** `+1`/`eyes` 둘로 "반영/후속"만 표현한다. 그보다 세밀한 상태가 필요해지면 본문 절로 올려야 한다 — 리액션 종류를 늘리는 쪽으로 가면 사람이 규약을 못 외운다.
- **병렬 금지.** 티켓 브랜치를 `origin/<통합>`에서 따는데 앞 티켓의 스쿼시 머지가 그 tip을 옮긴다. 게다가 같은 트랙의 티켓들은 파일이 겹친다.

## 완료 기준

인자로 준 티켓 전부가 CLOSED이고, 통합 PR 티켓 표에 각각의 머지 SHA가 있고, 처리된 주입 코멘트에 리액션이 붙어 있고, 러너가 남긴 주의·미달 AC가 사용자 보고에 옮겨져 있다.
